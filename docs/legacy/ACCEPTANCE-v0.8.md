# ShipCheck Studio v0.8.0 · 本机统一扫描验收（当前版本）

- [ ] `manifest.json` 和侧边栏 / Workspace 均显示 `0.8.0`。
- [ ] 访问自己的 HTTP(S) 站点，点击 **一键扫描全站**，应只请求本域读取权限。
- [ ] 允许后无需切换到 Search Lab 再点扫描；待进度完成后可看到站点汇总、逐页 QA 问题和 SEO/GEO 发现。
- [ ] 访问包含至少两个 HTML 页面的站点，确认会依照导航、Sitemap、渲染链接发现并检查多个 URL。
- [ ] 访问一个有意返回 404 的链接，确认标注技术问题，且该 URL 的浏览器 QA 显示未验证。
- [ ] 访问 CSR 网站，确认源 HTML 正文少而渲染正文多时产生有证据的风险提示；无法对比时显示未验证。
- [ ] 在设置中将上限从 20 改为 10 / 50，确认生效；大站点不应声称未扫描部分已通过。
- [ ] 在窄 Side Panel 中左右滑动 Tab，滚动滚轮、鼠标拖动、点击左右箭头均应显示隐藏标签；激活标签自动定位。
- [ ] 点击 **仅扫当前页**，确认只更新当前页检查，不触发全站抓取。
- [ ] 展开 **问题检查** 中多个 URL，查看全站 QA / SEO/GEO 问题；导出 Markdown 及 Agent JSON 并检查内容。
- [ ] 修改源码并重新检查；确认版本差异与已有验收记录按预期保留。
- [ ] 禁止站点权限后，确认不会产生虚假的成功扫描报告。
- [ ] 如果启用模型内容语义审计，必须主动提供 API、Key 并勾选授权；默认一键扫描不向第三方模型发送内容。

**未完成的验证不可填写“通过”：** 本机 Chrome 扩展的真实权限、真实站点多页面路由、动态认证页面、跨域页面、Google/Bing 实际索引状态不属于当前开发环境的模拟测试结论。

## v0.6.0 搜索准备度验收补充

1. 安装插件后在设置中确认 `Technical SEO` 与 `GEO / AEO 内容线索` 均开启。
2. 扫描网页，打开 `SEO / GEO` 标签：应显示 SEO、GEO、AEO 分组、证据状态和导出操作。
3. 对含合法 JSON-LD 的页面显示「已检测」；含错误 JSON-LD 时显示「需关注」，但不声称实际富媒体结果可用。
4. 对 `noindex` 页面显示需复核，不自动推断预览站是错误。
5. 未提供 robots.txt、Google Search Console 的情况下，必须显示「未验证」，不显示排名或 AI 引用率。
6. 大屏工作台左侧应显示搜索准备度摘要；旧版扫描结果显示「尚未采集」，不报错。
7. 使用 `node --test tests/*.test.cjs` 运行纯逻辑回归测试。

# ShipCheck Studio v0.6.0 · 本机验收清单

本清单用于对 ZIP 中的真实扩展进行验收。自动化核心测试不替代 Chrome 权限弹窗、真实截图和用户操作验证。

## A. 静态校验（已具备可执行命令）

- [ ] `node --test tests/core.test.cjs`：测试全通过。
- [ ] `node --check` 扫描核心和 UI JS：没有语法错误。
- [ ] ZIP 内包含 `manifest.json`、`src/studio`、`mcp/server.js`、`mcp/cdp.js`、`src/vendor/axe.min.js`。
- [ ] `manifest.json` 版本号和界面版本号均为 `0.6.0`。

## B. 插件本机 Chrome 测试

1. [ ] 解压文件；在 Chrome `chrome://extensions` 加载 `shipcheck-ai/`。
2. [ ] 打开 `tests/acceptance.html`（建议通过本机静态 Web Server：`python3 -m http.server 8765 --directory tests`，打开 `http://127.0.0.1:8765/acceptance.html`）。
3. [ ] 点击扩展图标打开 Side Panel，点击「开始交付检查」。
4. [ ] 扫描结果应出现水平溢出、`href="#"` 等问题；未配置业务实收验证的项目应保持「待验证」。
5. [ ] 在项目画像中切换网站类型，例如 B2B，并点击「按类型重建计划」；出现针对 B2B 的询盘路径相关验收项。
6. [ ] 人工设置一项业务验收为「通过」，填写证据；刷新侧边栏后仍能看到状态和备注。
7. [ ] 在问题列表点击「网页中定位」，确认目标 DOM 上出现临时标注，约 11 秒后移除。
8. [ ] 点击「全屏检查」，可在独立标签页看到项目目标、清单、已发现问题和修复指令。
9. [ ] 不开启视觉基线时，截图缺失应显示占位提示而非伪造预览。
10. [ ] 开启视觉基线并重新扫描后，Workspace 显示最新截图；如果某种视口没有截图，切换到该视口应提示不可用。
11. [ ] 点击「复制完整 Agent 修复任务」，内容应包含项目目标、DOM 定位、证据、非破坏性约束、复测要求。
12. [ ] 导出 Markdown 验收报告，核对“已确认/待验证”区分与扫描页面一致。
13. [ ] 在同一 URL 上修复一个问题，事先标记「修复中」，重新扫描后查看“已修复”列表；在**不同页面**扫描不应把它误判为已修复。
14. [ ] 将目标站点换成另一个域名，旧站点的验收计划与人工记录不应串站。

## C. MCP / CI 本机测试

```bash
# 需要 Node 22+、本机 Chrome
node mcp/server.js --ci http://127.0.0.1:8765/acceptance.html --fail-on high --json /tmp/shipcheck-test.json
```

- [ ] 能启动隔离 Chromium、加载测试页并返回 JSON 证据。
- [ ] 对带已知缺陷的测试页，退出码符合预期的阈值规则。
- [ ] 对不可访问 URL 返回工具错误和非 0 退出码，不能拿 Chrome 错误页生成“通过”报告。
- [ ] MCP 客户端能完成 `initialize`、`tools/list`、`tools/call`。
- [ ] 同进程 `shipcheck_scan` → 修复代码 → `shipcheck_verify` 返回新增/消失/仍存在的规则。

## D. AI 语义复核（可选）

- [ ] 未填写 API/未勾选同意，不发起网络请求。
- [ ] 填写兼容 API、模型、Key 并授权后可发送所选问题的**文本证据**，返回模型建议。
- [ ] API Key 只保留在当前 UI 输入框，不进入 `chrome.storage.local`、Markdown 报告或截图。
- [ ] API 无权限、模型错误、超时、CORS 失败时提供可理解的错误提示。
- [ ] 模型输出作为普通文字展示，不执行 HTML 或脚本。

## 本版明确不承诺

- 不保证发现所有视觉缺陷；不是所有网站都可嵌入 iframe。
- 不保证技术分数与真实交付能力成比例。
- 不自动证明服务端真的收到了表单，也不会未经授权提交真实业务请求。
- 不自动修复源码；修复应交给有源码权限的编程 Agent 或开发者执行，再复测。
- 不声称通过某次扫描就满足全部 WCAG、SEO 或安全标准。
